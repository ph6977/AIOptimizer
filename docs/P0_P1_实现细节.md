```

│      (Cherry Studio / Open WebUI / 任意 OpenAI 客户端)     │
└──────────────────────┬──────────────────────────────────┘
                       │ OpenAI 兼容协议 (HTTP/SSE)
                       ▼
┌─────────────────────────────────────────────────────────┐
│              FastAPI 网关 (gateway.py, :8000)             │

│  请求管线：                                               │
│  1. parse_chat_request   解析为内部 ChatCompletionRequest  │
│  2. compressor.compress  上下文压缩（超预算时触发）          │

│  4. prompt_enhancer      系统提示词注入                    │
│  5. ProviderFactory.create → adapter.chat_completion      │
│  6. log_usage            SQLite 用量落库                  │
└──────────────────────┬──────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│         PySide6 GUI (main.py 单进程模式)                   │
│   用量面板 │ 压缩透明 │ 会话管理 │ 设置                      │

| 形态 | 命令 | 说明 |
|------|------|------|

| 纯网关 | `uvicorn app.core.gateway:app` | 供外部客户端直连 |

### 2.1 配置系统 config.py

**文件**：`app/core/config.py`（210 行）

基于 **Pydantic v2 BaseSettings**，三层配置源优先级：`环境变量 > .env > 代码默认值`。

#### ProviderConfig 模型

```python
class ProviderConfig(BaseSettings):
    name: str                    # 内部标识，如 "openai" / "deepseek"
    display_name: str            # UI 显示名
    api_key: str = ""            # 密钥（建议 .env 配置）
    base_url: str = ""           # 空 = 用 Provider 默认地址
    models: list[str] = []       # 参与路由的模型列表
    enabled: bool = True         # 禁用后不参与路由
    priority: int = 0            # 数值越小优先级越高，路由加分项
    extra: dict[str, Any] = {}   # 扩展字段
```

#### Settings 核心配置项

| 分组 | 字段 | 默认值 | 说明 |
|------|------|--------|------|
| 网关 | `gateway_host` / `gateway_port` | `127.0.0.1` / `8000` | 监听地址 |
| 压缩 | `compression_enabled` | `True` | 总开关 |
| 压缩 | `compression_aggressiveness` | `0.5` | 激进度 0~1 |
| 压缩 | `max_context_tokens` | `8192` | 超过触发压缩 |
| 压缩 | `target_context_tokens` | `4096` | 压缩后目标值 |
| 压缩 | `compression_keep_recent` | `4` | 保留最近 N 条消息不压缩 |
| 压缩 | `compression_target_ratio` | `0.5` | 目标压缩比 |
| 压缩 | `compression_min_keep_tokens` | `500` | 防止过度压缩下限 |
| Judge | `judge_model` / `judge_api_key` / `judge_base_url` | `deepseek-chat` / 空 / DeepSeek 官方 | LLM 评估 |
| 路由 | `routing_enabled` | `True` | 智能路由开关 |
| 路由 | `quality_vs_cost` | `0.5` | 质量/成本权重 0~1 |
| 增强 | `prompt_enhancement_enabled` | `True` | 提示词增强开关 |

#### Provider 列表的序列化存储

Provider 列表以 JSON 字符串存在 `providers_json` 字段中，运行时由 GUI 动态增删改：

```python
def get_providers(self) -> list[ProviderConfig]:
    data = json.loads(self.providers_json)
    return [ProviderConfig(**p) for p in data]

def set_providers(self, providers: list[ProviderConfig]) -> None:
    self.providers_json = json.dumps([p.model_dump() for p in providers], ensure_ascii=False)
```

解析失败（JSON 非法/字段错误）时**安全回退为空列表**，不会抛异常导致启动失败。

#### 数据目录跨平台

```python
Windows:  %APPDATA%\AIOptimizer
Linux:    ~/.local/share/AIOptimizer
```

全局单例 `settings = Settings()`，另设 `runtime_config: dict` 存放运行时临时配置（不持久化）。

### 2.2 数据库层 db.py

**文件**：`app/core/db.py`（262 行）

基于 **aiosqlite** 全异步，避免阻塞事件循环。

#### 表结构 `usage_logs`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PK | 自增主键 |
| `timestamp` | DATETIME | 默认 `CURRENT_TIMESTAMP` |
| `provider` / `model` | TEXT | 服务商 / 模型 |
| `request_tokens` / `response_tokens` / `total_tokens` | INTEGER | token 统计 |
| `cost_usd` | REAL | 估算成本（美元） |
| `compressed` | BOOLEAN(0/1) | 是否压缩 |
| `original_tokens` / `saved_tokens` | INTEGER | 压缩前 / 节省量 |
| `request_id` / `session_id` | TEXT | 请求关联 / 会话统计 |

**索引**：`idx_usage_timestamp`（时间范围查询）、`idx_usage_session`（会话级统计）。

#### 关键实现点

1. **延迟初始化**：全局 `DB_PATH` 缓存，`get_db()` 首次调用时自动 `init_db()`。
2. **Windows 路径兼容**：aiosqlite 在 Windows 上不支持 `file://` URI，统一用 `str(DB_PATH)` 原始路径连接。
3. **row_factory**：设为 `aiosqlite.Row`，查询结果可按列名访问。

#### 统计查询 `get_usage_stats(days=7)`

一次返回四组数据（全部基于 `timestamp >= datetime('now', '-N days')`）：

```python
{
    "summary":     {requests, total_tokens, total_cost, saved_tokens},
    "by_provider": [{provider, requests, tokens, cost}, ...],
    "by_model":    [{model, requests, tokens, cost}, ...],
    "daily":       [{day, requests, tokens, cost}, ...],   # 按日分组，供趋势图
}
```

其中节省 token 的 SQL 技巧——只在压缩请求上累计：

```sql
SUM(CASE WHEN compressed THEN saved_tokens ELSE 0 END) as saved_tokens
```

### 2.3 上下文压缩引擎 compressor.py

**文件**：`app/optimizer/compressor.py`（316 行）

**核心策略：两阶段（分类 → 预算分配压缩）**，token 计数基于 tiktoken `cl100k_base`。

#### 阶段一：消息分类

每条消息被分类为三种动作之一（`CompressionAction`）：

- **keep** — 保留原文
- **summarize** — 压缩为摘要
- **drop** — 直接丢弃

启发式规则（`_classify_by_heuristics`，不调用 LLM，零成本）：

```
1. system/developer 消息           → keep（永远保留）
2. 含代码块 ``` 或命中 KEEP_KEYWORDS → keep
   （KEEP_KEYWORDS 覆盖：代码/函数/错误/架构/API/密码/配置/路径等 30+ 关键词）
3. 短消息(<50字) 且命中 DROP_KEYWORDS → drop
   （DROP_KEYWORDS：你好/谢谢/好的/哈哈等寒暄词）
4. 长文本(>500字) 且非关键           → summarize
5. 其他                             → keep（默认保留）
```

预留了 `_classify_by_llm` 接口（带 `hash` 缓存），未来可切换为廉价 LLM 精细分类，当前回退到启发式。

#### 阶段二：预算分配压缩（`compress()`）

```
输入: messages, target_tokens(默认4096), keep_recent(默认4)

1. 总 token ≤ target → 直接返回（no-op），stats 标记 saved=0
2. 拆分：system_messages │ other_messages
3. other_messages 再拆：to_compress(旧) + recent_messages(最近 keep_recent 条)
   ※ keep_recent=0 时压缩全部非系统消息（评测用激进模式）
4. 预算计算: budget = target - system_tokens - recent_tokens
   预算 ≤ 0  → 只保留 system + recent，全部旧消息 drop
5. 贪心分配（从旧到新遍历）：
   - keep 类:       tokens ≤ budget      → 保留原文，budget 扣减
   - summarize 类:  tokens ≤ budget*0.3  → 生成摘要（前200字符 + "[摘要]"前缀），
                                            budget 扣 tokens//3（约省 2/3）
   - 其余           → drop
6. 组装: system + [历史对话摘要] + kept + recent
```

#### 返回统计

```python
stats = {
    "original_tokens", "compressed_tokens", "saved_tokens", "saved_ratio",
    "kept", "summarized", "dropped",
    "details": [{role, action, reason, tokens}, ...]   # 逐条决策明细，供透明页展示
}
```

单例导出：`compressor = Compressor()`

### 2.4 智能路由 router.py

**文件**：`app/optimizer/router.py`（343 行）

#### 任务类型检测 `detect_task_type()`

6 种任务类型：`chat / code / reasoning / vision / creative / analysis`。

- 取**最后一条用户消息**做关键词计分（`TASK_KEYWORDS` 每类 8~11 个中英文关键词）
- 得分最高者胜出，全 0 分回退 `chat`

#### 难度估算 `estimate_difficulty()`

```python
difficulty = (min(总长度/10000, 1) + min(消息数/20, 1)) / 2   # 0~1
```

#### 模型能力矩阵 `MODEL_CAPABILITY`

内置 **17 个主流模型 × 6 种任务** 的能力评分表（0~1），覆盖：

| 厂商 | 模型 |
|------|------|
| OpenAI | gpt-4o / gpt-4o-mini / gpt-4-turbo / gpt-3.5-turbo |
| DeepSeek | deepseek-chat / deepseek-reasoner |
| GLM | glm-4 / glm-4v |
| Qwen | qwen-max / qwen-plus / qwen-turbo |
| Kimi | moonshot-v1-8k/32k/128k |
| Anthropic | claude-3.5-sonnet / claude-3.5-haiku |
| Gemini | gemini-1.5-pro / gemini-1.5-flash |

#### 路由评分公式 `route()`

对每个候选 `(provider, model)` 计算：

```python
task_score        = MODEL_CAPABILITY[model][task_type]     # 无记录默认 0.5
difficulty_match  = 1 - abs(task_score - difficulty)       # 能力-难度匹配度
cost              = input_cost + output_cost               # 每 1k token 成本
cost_factor       = 1/(1 + cost*100) if cost>0 else 1.0    # 成本衰减因子

score = quality_vs_cost * task_score * difficulty_match
      + (1 - quality_vs_cost) * cost_factor
      + (10 - provider.priority) * 0.01                    # 优先级微加成
```

取最高分；候选为空时抛 `ValueError("No models available")`；`routing_enabled=False` 或无 provider 时回退"第一个可用 Provider 的第一个模型"。

#### 可用模型发现 `get_available_models()`

遍历 `enabled && api_key` 的 Provider 的模型列表，从 `ProviderFactory._get_model_overrides()` 查 `ModelInfo` 元数据；**查不到的未知模型自动构造默认 ModelInfo**（context_window=8192，成本 0）而不是跳过——此设计保证了自定义/Mock 模型也能参与路由。

单例导出：`router = Router()`

### 2.5 提示词增强 prompt_enhancer.py

**文件**：`app/optimizer/prompt_enhancer.py`（91 行）

#### 增强提示词库

按 6 种任务类型预置专家角色系统提示词（`ENHANCED_SYSTEM_PROMPTS`）：

| 任务类型 | 角色定位 | 核心指令要点 |
|----------|----------|--------------|
| chat | 有用/无害/诚实的助手 | 自然专业的语言 |
| code | 资深软件工程师 | 简洁可维护、标准库优先、类型注解、YAGNI |
| reasoning | 逻辑严密的推理助手 | 逐步推理、明确前提、结构化输出+置信度 |
| vision | 视觉理解专家 | 事实/推测分离、准确转录、结构化描述 |
| creative | 创意写作助手 | 风格适配、去 AI 感、严格约束、多版本 |
| analysis | 数据/文本分析师 | 明确方法、背景-方法-发现-结论结构、量化优先 |

另附加通用 `QUALITY_GUIDELINES`（无废话/信息完整/格式清晰/代码可运行）。

#### 合并策略 `enhance()`

```
已有 system 消息 → 合并：原提示词 + "\n\n" + 增强提示词（只合并第一条，避免重复注入）
无   system 消息 → 头部插入新 system 消息
```

复用 router 的 `detect_task_type()`，无需重复实现任务分类。单例导出：`prompt_enhancer`。

### 2.6 Provider 适配层 providers/

**文件**：`app/providers/__init__.py`（625 行）

#### 抽象基类 ProviderAdapter（ABC）

```python
class ProviderAdapter(ABC):
    @property provider_name / default_base_url        # 标识
    @abstractmethod list_models()                     # 模型列表（带缓存 _models_cache）
    @abstractmethod chat_completion(request)          # 非流式
    @abstractmethod chat_completion_stream(request)    # SSE 流式
    @abstractmethod _get_headers()                    # 认证头
    _get_client()                                     # httpx.AsyncClient 惰性创建
                                                      #   (超时 60s / 连接 10s)
    estimate_cost(model, in_tok, out_tok)             # 基于 ModelInfo 价格估算
    close()                                           # 连接池释放
```

#### 三个具体适配器

| 适配器 | 覆盖服务商 | 协议特点 |
|--------|-----------|----------|
| `OpenAICompatibleAdapter` | openai / deepseek / glm / qwen / kimi / ollama | 统一 OpenAI Chat Completions 协议，支持 `model_overrides` 注入模型元数据 |
| `AnthropicAdapter` | Claude 系列 | Messages API，请求/响应格式转换 |
| `GeminiAdapter` | Gemini 系列 | generateContent 协议；流式暂以"非流式+模拟分片"实现 |

#### 数据类

```python
ModelInfo(id, display_name, context_window,
          input_cost_per_1k, output_cost_per_1k, capabilities)
ChatMessage(role, content, name=None)
ChatCompletionRequest(model, messages, temperature=0.7,
                      max_tokens=None, stream=False, extra={})
ChatCompletionResponse(id, model, choices, usage)
```

#### ProviderFactory

- **适配器缓存**：`_adapters: dict[key, ProviderAdapter]`，key = `"{name}:{api_key前8位}"`，同一配置复用连接池
- **模型元数据表** `_get_model_overrides()`：内置各厂商模型的 context_window / 价格 / 能力标签，供路由评分与成本估算使用
- 未知 provider 名抛 `ValueError`

### 2.7 FastAPI 网关 gateway.py

**文件**：`app/core/gateway.py`（约 450 行）

#### 端点一览

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/health` | 健康检查 `{status, version}` |
| GET | `/v1/models` | 聚合所有启用 Provider 的模型列表（`{provider}/{model_id}` 格式） |
| POST | `/v1/chat/completions` | 核心优化管线（流式/非流式） |
| GET | `/v1/usage/stats?days=N` | 用量统计（GUI 面板数据源） |
| GET | `/v1/config` | 当前配置（api_key 脱敏为 `has_key: bool`） |
| POST | `/v1/config` | 运行时热更新配置（setattr，不持久化） |

#### 核心管线 `chat_completions()`

```python
1. 解析请求体 → parse_chat_request() → ChatCompletionRequest
   （header x-session-id 提取会话 ID，默认 "default"）
2. providers = build_provider_configs()      # 空 → 503
3. 压缩: compression_enabled 且消息数>1 时执行
       compressor.compress(messages, target, max_context)
4. 路由: routing_enabled 且 model 为空时执行
       router.route() → 决定 provider + model
   否则: 按 "provider/model" 前缀解析，或回退第一个可用
5. provider 校验: 找不到或无 api_key → 503
6. 增强: prompt_enhancer.enhance(messages)
7. adapter = ProviderFactory.create(provider_config)
8. 转发:
   - stream=True  → StreamingResponse(SSE)，流结束后异步 log_usage
   - stream=False → adapter.chat_completion()，响应注入 optimization 元数据后返回
9. 异常映射:
   - httpx.HTTPStatusError → 上游状态码 + 响应文本
   - httpx.RequestError    → 502 Upstream unreachable
   - Exception             → 500 + 完整 traceback 打印到控制台
```

#### 响应中的优化元信息（非流式）

```json
{
  "id": "...", "choices": [...], "usage": {...},
  "optimization": {
    "compression": {"enabled": true, "saved_tokens": 1234, "saved_ratio": 0.42, ...},
    "routing": {"provider": "deepseek", "model": "deepseek-chat", "reason": "任务类型:code, 难度:0.35, 评分:0.78"}
  }
}
```

响应头带 `X-Request-ID` 和 `X-Compression`（enabled/disabled），便于客户端侧观测。

#### 全局异常处理器

```python
@app.exception_handler(Exception)
async def global_exception_handler(request, exc):
    print(f"[Global ERROR] {request.url} - {traceback.format_exc()}")
    return JSONResponse(500, {"detail": f"Internal server error: {exc}", "path": str(request.url)})
```

保证任何未捕获异常都返回**结构化 JSON 错误**（含出错路径），而非空响应体——这是排查 500 问题的关键改进。

#### 测试模式 Mock 注册 `_register_mock_provider()`

`AIOPTIMIZER_TEST_MODE=1` 时在 lifespan 启动阶段执行，做三件事：

1. **猴子补丁 `ProviderFactory.create`**：`name=="mock"` 时返回进程内 `MockProviderAdapter` 单例，其余走原逻辑
2. **猴子补丁 `_get_model_overrides`**：为 `mock-model` / `mock-model-vision` 注册 ModelInfo 元数据
3. **注入 ProviderConfig**：`settings.set_providers([mock_config])`

> 实现教训：猴子补丁替换 classmethod 时，补丁函数**不能带 `cls` 参数**（普通函数赋值给类属性后，调用方 `ProviderFactory.create(config)` 只传一个实参），否则报 `missing 1 required positional argument`。

#### MockProviderAdapter

- 内置 **14 组关键词→高质量中文回答** 映射（装饰器/RESTful/单例/LRU/斐波那契/逻辑推理/五言绝句等），未命中时回退 `"这是一个模拟回复。收到：" + 前100字`
- 流式：按 10 字符分片 + `asyncio.sleep(0.01)` 模拟打字机效果，SSE 格式 `data: {...}\n\n`，结尾 `data: [DONE]`
- usage 按 `len(content)//2` 粗估 token

### 2.8 PySide6 GUI

### 3.2 评估运行器 run_eval.py

**文件**：`app/eval/run_eval.py`（613 行）

**对比式评估**：每个用例跑两遍——

- **回答 A**：无压缩（原始上下文直通）
- **回答 B**：走完整优化管线（压缩 → 路由 → 增强）

然后交给 Judge 对比打分。

#### Mock 模式的压缩降质模拟

真实对比需要真实 LLM 才能看到压缩质量损失；Mock 模式通过**确定性降质函数**模拟：

```python
def _degrade_response(response_text, comp_stats):
    saved_ratio = comp_stats["saved_ratio"]
    keep_ratio  = 1 - saved_ratio * 0.6        # 压缩越多，保留信息越少（最多丢60%）
    degraded    = response_text[:keep_len]
    degraded   += f" [压缩丢失 {saved_ratio:.0%} 信息]"   # 降质标记
```

评测时强制激进压缩参数（`target_tokens=10, keep_recent=0`），确保压缩必然触发。

#### Mock 评分：多维启发式（0~5 分）

```python
score = 长度分(0-2, len/150)
      + 关键词覆盖(0-2, 10个通用词 × 0.3)
      + 结构化分(0-1, 含"1."/"步骤"/"```"等标记)
      + 相关性分(0-1, 问题-回答词集交集 × 0.2)
```

附加规则：回答 B 含 `[压缩丢失` 标记且长度 < A 的 80% 时**额外扣 1 分**。

#### 聚合报告 `_aggregate()`

```python
{
  "timestamp", "total_cases", "valid_cases",
  "avg_score_a", "avg_score_b", "score_diff",     # B-A 差值
  "winners": {A, B, tie},
  "by_type": {chat: {avg_a, avg_b, winners}, code: {...}, ...},
  "details": [逐用例明细]
}
```

同时输出 JSON + Markdown 双格式到 `eval_reports/`。

### 3.3 LLM-as-Judge 双模式

`judge()` 方法三级策略：

| 优先级 | 模式 | 触发条件 | 实现 |
|--------|------|----------|------|
| 1 | Mock 启发式 | `use_mock=True` | 上述多维评分，零成本，CI 可跑 |
| 2 | **真实 DeepSeek Judge** | `settings.judge_api_key` 非空 | 直接 POST `{judge_base_url}/chat/completions`，temperature=0.1，从回答中提取 JSON（`find("{")` ~ `rfind("}")`） |
| 3 | 网关回退 | 无 Key | 经网关转发 judge 请求 |

Judge Prompt 要求四维评估（准确性/完整性/实用性/清晰度），输出严格 JSON：

```json
{"score_a": 1-5, "score_b": 1-5, "winner": "A|B|tie", "reason": "..."}
```

### 3.4 压缩参数校准

P1 阶段将压缩行为参数化并加入 Settings（见 2.1 表格）：

- `compression_keep_recent=4` — 生产默认：保留最近 4 轮完整对话，兼顾上下文连贯与压缩率
- `compression_target_ratio=0.5` — 目标压缩一半
- `compression_min_keep_tokens=500` — 下限保护，防止压没了

**评测验证结论**：Mock 评分能明确区分压缩/未压缩质量（典型结果 A 胜 14 / B 胜 0 / 平 2），证明评估管线对质量差异敏感，可用于后续真实模型的压缩率-质量权衡调参。

## 四、关键 Bug 修复记录

### 4.1 Gateway /v1/chat/completions 返回 500（本次会话核心修复）

**排查路径**：500 + 空响应体 → 添加全局异常处理器拿到结构化错误 → 逐层暴露三个叠加 Bug：

| # | 根因 | 修复 |
|---|------|------|
| 1 | 空响应体无法定位错误 | 添加 `@app.exception_handler(Exception)` 全局处理器，返回 `{"detail", "path"}` JSON + 控制台打印完整 traceback |
| 2 | `"No models available"`：Mock 模型不在 `_get_model_overrides` 元数据表，`get_available_models()` 直接跳过 → 候选为空 | 双保险：① router 对未知模型构造默认 ModelInfo；② 测试模式猴子补丁注册 mock 模型元数据 |
| 3 | 猴子补丁 `patched_create(cls, provider_config)` 以普通函数替换 classmethod，`cls` 抢占实参 → `missing 1 required positional argument` | 去掉 `cls` 参数，函数体内直接引用 `ProviderFactory` 类 |

**修复后端到端验证**：

```
POST /v1/chat/completions → 200
  model: mock-model（路由自动选择）
  routing.reason: "任务类型:code, 难度:0.03, 评分:0.73"

```

### 4.2 仪表盘空值崩溃

SQLite 空表聚合 `SUM()` 返回 **NULL**（键存在值为 None），`summary.get('total_tokens')` 拿到 None 后格式化崩溃。修复：`or 0` 模式统一兜底。

### 4.3 Windows aiosqlite 路径

Windows 上 `file://` URI 不被支持，统一改用 `str(path)` 原始路径连接。

### 4.4 .bat 启动脚本中文路径问题（已放弃脚本方案）

cmd.exe 对含中文路径的 `cd`/`set` 处理不稳定，PowerShell 亦有编码问题。**结论：放弃启动脚本，保留 `python main.py` 直接启动方式**，相关脚本文件已全部清理。
